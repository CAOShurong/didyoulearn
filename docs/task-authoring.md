# Authoring a task pack

A task pack is a compact measurement instrument, not a collection of trivia questions.

## 1. Define one transferable concept

Write observable objectives. “Understand p-values” is too vague. “Reject the reversal of
`P(data | null)` into `P(null | data)` in a new domain example” is testable.

## 2. Map misconceptions before writing items

Each misconception should describe a plausible wrong model of the concept. Critical errors are the
subset that make a teaching run unsafe or uninterpretable.

## 3. Cite stable sources

Prefer standards bodies, textbooks with clear licensing, official documentation, and peer-reviewed
work. A source supports correctness; it does not by itself validate the assessment.

## 4. Write equivalent forms

Pretest and post-test forms should target the same objectives at comparable difficulty without
reusing wording or answers. Transfer items must change the surface context or require a genuinely
new application.

## 5. Keep held-out items away from the tutor

The tutor receives the learning objectives, learner profile, instructions, boundaries, and allowed
source material. It must not receive the assessment items.

## 6. Review in layers

- `community-draft`: schema-valid and source-linked, without a named expert review.
- `reviewed`: maintainers documented content and equivalent-form review.
- `expert-reviewed`: a named domain expert and review record are available.

The label describes evidence, not prestige.

## 7. Pilot before ranking

Check item difficulty, distractor behavior, missing responses, ceiling and floor effects, and
equivalent-form differences with learners who resemble the intended population. Revise the task
version whenever interpretation changes.
